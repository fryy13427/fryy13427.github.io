我们下载好文件后先放在 die 里面查壳，顺便得到本题的基本信息。如图所示：由 die 我们可以清楚知道本题是需要 Linux 系统，语言是 C 等基本信息。也明确我们下一步可以到 wsl 里面去裸跑一遍获得信息。以下为裸跑得到的信息。

至此我们把已知的信息搜集好后，将文件放在 ida 里面开始逆向。进入 ida 后我们在左侧的 function name 窗口就可以看到 start。

看到 main 主函数，我们进去看看就可以看到本题判断的逻辑如图。

（这里截图不全可以自己去看看）在这里就可以印证前面在 wsl 中裸跑的情况。在 C 伪代码中可以看到 memcmp(&v6, &unk_2020, v4)：其中 v4 = strlen(s) = 49，是比较的字节数；&v6 指向 VM 结构的输出缓冲区，存放我们的输入经 VM 执行后产生的 49 字节结果；&unk_2020 则是固定的 49 字节目标数据。因此接下来转向 &unk_2020 查看比对目标。

（这里我们找 49 个）这就是与我们 flag 比较的 flag 密文。但前面 c 伪代码中我知道这些数是经过运算得到的。在 C 伪代码图中我们看到我们输入的数经过：

进入这三个函数我们知道输入先被“编译”成自定义指令，再由自定义 VM“执行”，执行结果拿去比对——这就是本题叫 ez_Vm 的原因。已知密文和加密方式之后就可以得到正确的 flag。

到这里就是自己看代码的能力和写脚本解码的能力了。我是交给 ai 跑出来的。

加密逻辑为：

  • 7 字节模板表：[1, c, 2, 0x0A, 3, 7i+3, 4]，末尾 0xFF 停机
  • opcode 表：1=赋值、2=异或、3=加法、4=输出、0xFF=停机
  • 一行公式：out[i] = ((c ^ 0x0A) + (7i+3)) & 0xFF，逆推 c = ((t[i] - (7i+3)) & 0xFF) ^ 0x0A

得到 flag 为：msctf{VM_Pr0t3ct10n_T3chn0l0gy_Rev3rs3_Ch4ll3ng3}
